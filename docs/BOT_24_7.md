# Бот 24/7 — почему не ONREZA и что делать

## Почему раньше «само работало»

На **Vercel** бот получал сообщения по **webhook**: Telegram → ваш URL → ответ. Исходящие запросы на `api.telegram.org` с Vercel **обычно проходили**.

На **ONREZA** админка и база работают отлично, но с серверов платформы **нет нормального доступа к Telegram Bot API** (ни long polling, ни стабильные исходящие вызовы). Поэтому бот **нельзя** надёжно держать только внутри того же процесса, что и сайт.

**Схема сейчас:**

| Часть | Где |
|--------|-----|
| Админка + PostgreSQL | ONREZA |
| Telegram-бот | Отдельный процесс **poller** (`scripts/telegram_poller.py`) там, где есть доступ к Telegram |

Пока poller крутится **на Mac** — бот жив. Mac выключен — бот молчит. Это не «поломка», а временная схема.

## Как сделать «всегда», как раньше

Нужен **всегда включённый** маленький сервер **не ONREZA** (VPS или PaaS), только для poller. Те же переменные, что у бота:

- `BOT_TOKEN`
- `DATABASE_URL` (строка Postgres ONREZA/Kaiki — **та же**, что в панели ONREZA)

В ONREZA обязательно:

```bash
TELEGRAM_BOT_DISABLED=1
```

(чтобы веб-приложение не пыталось второй раз подключиться к Telegram)

---

### Вариант A — VPS (Timeweb, Selectel, Hetzner, ~200–500 ₽/мес)

1. Ubuntu 22.04, 1 vCPU / 512 MB достаточно.
2. На сервере:

```bash
sudo apt update && sudo apt install -y git python3.12 python3.12-venv
git clone git@github.com:k53303325-max/pes-data.git
cd pes-data
python3.12 -m venv venv
./venv/bin/pip install -r requirements.txt
```

3. Файл `/etc/pes-data-poller.env` (права `600`):

```bash
BOT_TOKEN=...
DATABASE_URL=postgresql://...
```

4. Systemd — скопируйте `deploy/systemd/pes-data-poller.service`, затем:

```bash
sudo systemctl enable --now pes-data-poller
sudo systemctl status pes-data-poller
```

5. Логи: `journalctl -u pes-data-poller -f`

---

### Вариант B — Docker (любой VPS)

```bash
cd pes-data
cp docs/env.poller.example .env.poller   # заполните BOT_TOKEN и DATABASE_URL
docker compose -f docker-compose.poller.yml up -d
```

---

### Вариант C — Mac всегда включён (компромисс)

Установите автозапуск при входе:

```bash
cp deploy/macos/com.pesdata.poller.plist ~/Library/LaunchAgents/
# отредактируйте пути и env в plist при необходимости
launchctl load ~/Library/LaunchAgents/com.pesdata.poller.plist
```

Mac должен быть включён и в сети — это не замена VPS, но лучше, чем запускать вручную.

---

### Вариант D — написать в поддержку ONREZA

Текст запроса:

> Нужен исходящий HTTPS к `api.telegram.org` (Telegram Bot API) из production-проекта `pes-data`. Сейчас long polling и вызовы Bot API с сервера не работают; админка на ONREZA, бот вынужденно на отдельном VPS.

Если они откроют доступ — можно будет снова включить бота **внутри** ONREZA (`TELEGRAM_BOT_DISABLED=0`, `TELEGRAM_POLLING=1`) и poller на VPS не понадобится.

## Проверка

- В Telegram: `/start` — ответ за несколько секунд.
- `https://api.telegram.org/bot<TOKEN>/getWebhookInfo` → `url` пустой (режим polling).
- В ONREZA `/health` → `"telegram_mode":"off"` при `TELEGRAM_BOT_DISABLED=1`.
